# 权限资源与 i18n 翻译约定

> 工程：Project_Aether  
> 适用：权限目录注册、权限管理 UI、各业务插件权限资源展示。

## 1. 核心原则

- **DB 存 key，界面再 `TR()`**：`perm_permission.display_name` 存 i18n source key，不存 `TR()` 后的译文。
- **权限 key ≠ 展示 key（Action）**：`key` 用于 `canAction` / FSM；`display_name` 存对应 UI 文案的 i18n key。
- **Nav/SubPage**：`key` 通常即 i18n key（如 `aoi.nav.home`），`display_name` 与 `key` 相同即可。

## 2. 注册 API（PermService / IPermCatalogRegistrar）

```cpp
// Nav / SubPage：第三参与 key 相同
registerNav(QStringLiteral("aoi.nav.home"), QStringLiteral("aoi.nav.home"), 20);
registerSubPage(QStringLiteral("aoi.nav.system.switch"), QStringLiteral("aoi.nav.system"),
                QStringLiteral("aoi.nav.system.switch"), 1);

// Action：第三参为插件内文案 key，禁止 TR()
registerAction(QStringLiteral("home.start"), QStringLiteral("aoi.nav.home"),
               QStringLiteral("aoi.sidebar.btn.start"));
```

| 参数 | Nav/Sub | Action |
| --- | --- | --- |
| `key` | 全局唯一，= i18n key | 业务短名（`home.start`） |
| `displayName` | = `key` | 插件 `.ts` 中的 source key |
| `pageKey` | 父 nav key | 所属 nav 或 sub_page key |

种子 SQL（`config/sql/*/003_seed_permissions.sql`）同样遵循：`display_name` 与 `key` 一致。

## 3. 展示层解析顺序

`permission_ui::permissionResourceDisplayText(key, displayName)`（`perm_i18n_utils.h`）：

1. `TR(key)` — Nav/Sub、seed 的 `perm.*` / `nav.*` / `sub.perm.*`
2. `TR(display_name)` — 业务 Action 的 i18n key
3. 回退 `display_name` 原文 — 人工创建、未配置 i18n 的资源

权限资源树搜索亦匹配上述本地化后的展示文本。

## 4. 翻译文件归属（qm 来源）

| key 前缀 / 范围 | `.ts` / `.qm` 位置 | 说明 |
| --- | --- | --- |
| `aoi.*` | `plugins/aoi/i18n/aoi_*.ts` | AOI 页面、侧栏按钮等 |
| `perm.common.*` `perm.users.*` … | `common/plugins/permission/i18n/permission_*.ts` | 权限插件 UI；`sourcelanguage=en_US` |
| `perm.users.query` 等 seed action | 同上 | `key` 即 source，与种子一致 |
| `nav.permission` `sub.perm.*` | `config/app_*.ts` | 顶栏权限容器，不进 permission 插件 ts |
| `nav.lighten.*` 等其它产品线 | 对应插件或 `app_*.ts` | 按插件注册约定 |

插件加载时：`LanguageManager::registerPluginTranslator("permission", "permission")` / `"aoi", "aoi"`。

## 5. 权限插件 UI 文案（PTXT）

- 宏：`PTXT("perm.xxx")`，source 为英文 key（见 `perm_text.h`）。
- 命名：`perm.common.*` 通用；`perm.err.*` 校验；`perm.users.*` / `perm.roles.*` / `perm.resources.*` / `perm.audit.*` / `perm.login.*` / `perm.datetime.*` 分模块。
- 内置角色：`perm.role.minimal.*`、`perm.role.super_admin.*`；列表展示用 `role.code` 判断，不靠中文 `name`。

## 6. 常见错误

| 错误做法 | 后果 |
| --- | --- |
| `registerAction(..., TR("aoi.xxx"))` | DB 固化启动时语言，切换语言不更新 |
| seed `display_name` 写中文 | 与 key 不一致，依赖展示层兜底 |
| 在 permission 插件 ts 里加 `aoi.*` | 职责混乱；应留在 AOI ts |
| Action 的 `key` 改成 `aoi.sidebar.btn.*` | 破坏 `canAction("home.start")` 等现有调用 |

## 7. 权限资源页只读目录

资源由**插件代码注册**（`registerNav` / `registerSubPage` / `registerAction`）及种子 SQL 入库，不在 UI 维护。

- 开关：`permission::kPermissionResourcesCatalogReadOnly`（`perm_system_constants.h`，默认 `true`）
- UI：隐藏新建/保存/重置/删除/启停按钮栏；详情表单只读
- ViewModel：`beginCreate*`、`saveEditor`、`deleteSelected`、`toggleSelectedEnabled` 等入口同样受开关拦截

恢复 UI 维护能力时，将该常量改为 `false` 并重新编译即可。

## 9. owner_plugin 与 Catalog Reconcile

### 9.1 字段含义

| 字段 | 说明 |
| --- | --- |
| `owner_plugin` | 归属 `PluginSpec::name()`（与 `*plugin.json` 的 `Name` 一致，如 `Aoi`、`Lighten`） |
| `source` | `seed`（Permission 种子，不参与 Reconcile 硬删）或 `plugin`（业务 `registerNav/SubPage/Action` 写入） |

种子行 `owner_plugin='Permission'`；业务插件在首次 insert 时由 `PermCatalogRegistrar` 写入当前 `PermCatalogScope` 的 owner。**key 已存在则幂等跳过，不更新 owner**（改库需删行或删库重建）。

### 9.2 注册时如何带上 owner

**插件 `initialize()`（或 `extensionsInitialized` 注册页）入口：**

```cpp
#include "aoi_plugin_name.h"  // ESS_DEFINE_PLUGIN_NAME(aoi)

aoi::setPluginName(pluginSpec()->name());
const PermCatalogScope scope(aoi::pluginName());
PS->registerNav(...);
```

**`PageWidget::onLoad` 内延迟注册**（已离开上述 scope）：

```cpp
const PermCatalogScope scope(aoi::pluginName());
PS->registerAction(...);
```

其它业务插件仿照：`lighten_plugin_name.h`、`motion_plugin_name.h`、`motioncontrol_plugin_name.h`。

### 9.3 Reconcile 规则（Phase 1）

启动后 `PermissionPlugin::extensionsInitialized()` → `QTimer::singleShot(0)` 调用 `reconcilePermissionCatalog()`。

| 条件 | 行为 |
| --- | --- |
| `owner_plugin` ∉ `deployedPluginNames()`（`plugins/` 目录未扫描到该 DLL） | **硬删**该 owner 资源子树，级联 `perm_role_permission` |
| `owner_plugin` ∈ deployed 且 ∉ `activePluginNames()`（DLL 在但本次未 Running） | **保留**资源与角色授权 |
| `owner_plugin` ∈ active 且未 disabled | `enabled=true` |

**现场含义**：从安装包去掉某插件 DLL → 下次启动清权限；仅启动失败（依赖/设备临时异常）→ **不丢角色勾选**。

**schema 变更**：无迁移脚本；删 `data/permission.db`（或 MySQL 整库）后由 `001_schema` + 种子 + 插件注册重建。

详见 `plugins/aoi/docs/AOI 检测软件 设计方案.md` §异常与安全 · 权限资源目录对齐。
