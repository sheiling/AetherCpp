# 修订记录 / 变更记录 — 合并策略

> 适用于：`plugins/aoi/docs/AOI 检测软件 设计方案.md` 的 `## 修订记录`，以及  
> `plugins/aoi/docs/AOI 检测软件 软件操作SOP.md` 文末 `## 变更记录`。  
> Agent 维护文档时**必须优先遵循本策略**。

---

## 决策顺序（必须按序执行）

```
1. 读取表格最后一行的「日期」→ lastDate（仅取 YYYY-MM-DD）
2. 确定本次维护日期 → todayDate（用户环境当前日期，或变更实际发生日）
3. 若 todayDate ≠ lastDate → 【必须追加新行】→ 结束（勿改旧行）
4. 若 todayDate = lastDate → 进入「同日合并」判断（见下）
5. 若正文完全未改 → 【跳过】不写记录
```

**跨自然日一律追加新行**，不要求「独立交付」才追加。  
**禁止**把新一天的摘要合并进旧日期的行，**禁止**修改已有行的日期列来冒充当日。

---

## 同日：合并到最后一条（不新增行）

**仅当** `todayDate = lastDate` 且满足以下**全部**条件时，只编辑**最后一行**摘要，用 **`；`** 追加：

1. 改动量小：约 1～3 个段落/小节；无新页面、无新对外流程
2. 非用户明确要求「单独记一条 / 升版本」
3. 摘要总长仍合理（单格建议 ≤120 字；过长则**同日也新开一行**）

设计方案：**版本号**同日合并时不递增；跨日新行时可小步递增（如 v0.2 → v0.3）。

### 同日合并示例

```markdown
| 2026-06-02 | 主页 §1.1 | 初始化弹窗灯板提示；未就绪禁用手动进料 | AI |
```

---

## 必须新增一行（末尾追加）

满足**任一**条件即追加（在「跨日」时第 3 步已命中，无需再判）：

| 条件 | 说明 |
| --- | --- |
| **跨自然日** | `todayDate ≠ lastDate`（**强制**，最高优先级） |
| **结构性变更** | 新模块/新页面/新对外流程或接口（设计方案） |
| **用户明确要求** | 单独版本号或单独变更条 |
| **初稿** | 表格尚无有效数据行 |
| **同日摘要过长** | 已是新主题，同日也新开一行 |

### 跨日追加示例

```markdown
| 2026-06-02 | v0.2 | §3.1 主页按钮置灰；§4.5 产品配置 | AI |
| 2026-06-03 | v0.3 | §4.7 参数修改自动记录 | AI |
```

---

## 跳过不写记录

正文也未改时，**不写**修订/变更记录：

- 纯绑定 bug、拼写、注释、格式化
- 与操作/架构无关且正文无需同步的内部实现

---

## 格式

**操作手册变更记录**：`日期 | 模块 | 变更摘要 | 操作人(AI)`

**设计方案修订记录**：`日期 | 版本 | 变更摘要 | 操作人`

---

## Agent 执行 checklist

1. 解析 `lastDate` 与 `todayDate`（**不得跳过**）
2. 跨日 → **追加新行**
3. 同日 → 合并或（摘要过长/结构性）新开一行
4. 合并时：**勿**改旧行日期
5. 自检：是否存在「不同日期却共用一个日期格」的行
